# ADR016: Private telemetry and durable operational metrics

Accepted implementation refinement,2026-10-12, within T26. HTTP and worker signals use explicit allowlists, never automatic model/content instrumentation. Public API routes never expose a scrape endpoint. An optional separate listener requires a mounted32-byte-or-longer bearer token, limits headers/concurrency/deadlines, and binds loopback by default. Container wildcard binding is explicit and must stay on the private service network. OTLP/HTTP can target loopback or the fixed private collector service only. No inherited proxy, credential-provider, endpoint or header environment is used by the exporter.

The existing database ledger remains authoritative and unsampled. `metrics-worker` uses a dedicated `ed_monitor` login with no tenant-table access, no writes and no RLS bypass. Its only application function is the fixed, argument-free `operational_metrics()` aggregate. A NOLOGIN owner holds the narrowly enumerated SELECT privileges needed by that function; results have bounded model/kind/state labels and no IDs, content or exception text. Runtime database timeout2s and a cached15s refresh prevent scrapes from running database work. Stale/failed snapshots expose failure and no stale measurements after45s.

Retained cost/token totals and current dead-job counts are **gauges**, not monotonic counters: retention and explicit job recovery may reduce them. This refines the earlier telemetry proposal's `_total` names. The ledger itself is not sampled or updated by monitoring. Collector failure can drop bounded in-memory telemetry; it must not affect authorization, effects, usage settlement or terminal run state. No shared read-privileged endpoint is exposed to workspace/browser credentials.

Native OpenTelemetry protobuf encoding is used with a small bounded HTTP transport because the standard exporter can inherit credential/proxy configuration and log upstream response details. The transport uses no redirects/retries, caps request/response sizes, imposes a timeout and treats partial rejection as failure. This is intentional lossy observability, not durable delivery. No new model transport abstraction or dependency is added. Instrumentation uses public saver overrides and code-owned graph/stage names; it never inspects checkpoint state or function arguments. Worker trace relationships and remaining signal coverage are tracked in the T26 report until tested.
