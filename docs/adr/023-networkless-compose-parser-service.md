# ADR023: Networkless parser service for local Compose

Selected for implementation2026-10-19 under the user's full-stack Compose request. This changes the local deployment mechanism; normalized blocks, format limits, source checksums, authorization, lease fencing and publication are unchanged. The operator-host `ParserSandbox` remains the default when no parser socket is configured.

The existing sandbox starts a new restricted Docker container for each document. A containerized ingestion worker cannot use that mechanism without a Docker control capability. Giving it the host Docker socket would allow that worker to control the host. A privileged nested Docker daemon adds another privileged service and image-distribution lifecycle. Neither is needed for this local capstone.

The Compose profile uses a dedicated parser container with **no network interface except loopback, no shared IPC memory mount, no host Docker socket and no application credentials**. Ingestion sends bounded source bytes through a private Unix-domain socket volume. The parser container never fetches URLs, storage objects, models or packages at runtime. The API, chat and other workers do not mount the socket.

The small supervisor runs as UID0 with only `SETUID` and `SETGID`; all other capabilities are dropped. Its sole writable mounts are the socket volume and a bounded root-only scratch tmpfs. The socket directory is root-owned0755; its socket is root:10001 mode0660. Ingestion mounts this volume read-only and connects as UID10001. Linux `SO_PEERCRED` permits only UID10001 and UID0 health checks. A browser cannot reach this interface, and the client cannot replace the socket directory entry.

Each accepted request creates a new Python process. Before importing format parsers it drops supplementary groups, switches permanently to UID/GID65532, changes working directory to `/`, applies no-new-privileges, installs an additional seccomp filter and sets hard resource limits. Only stdin metadata, the bounded stdout manifest, stderr `/dev/null`, and one **read-only source descriptor** survive process creation. Root-only scratch directories prevent the child from opening other request files; no request selects a filesystem path, command, image or parser module.

The child filter checks the Linux syscall architecture and rejects the x32 ABI. Linux x86_64 and aarch64 have explicit syscall tables; unsupported systems or a failed filter installation fail the extraction. Networking/socket creation, process inspection, new processes/executables, io_uring, named SystemV/POSIX IPC, keyrings and filesystem mutations are denied. File opens must be read-only; `openat2` is denied because its pointed-to options cannot be inspected safely by this filter. This prevents writable `/dev/shm`, message queues or other accidental mounts becoming a persistence channel between requests. The inherited manifest descriptor is the only regular-file output. These controls complement Docker's default seccomp and namespace boundaries; they are not a general-purpose code-execution sandbox.

The supervisor serves one request at a time with listen backlog1. The envelope is at most4096 bytes with duplicate-key/depth handling; source input is at most20MiB, received within30s and checked against its supplied SHA256 before parsing. The child receives60s wall time,60s CPU,1GiB address space,64 descriptors, no new processes, no core dumps and a256MiB output-file limit. The container receives1CPU,1280MiB memory without additional swap and32PIDs; its root-only tmpfs is320MiB. The supervisor detects client disconnect/trailing input and kills/reaps the owned child. It temporarily takes the child's effective UID to signal it, avoiding a `KILL` capability. Output transmission has a10s deadline; the worker's whole operation has a100s ceiling. Existing durable heartbeat/fencing continues while awaiting parsing.

The protocol contains version, operation, source length/digest, title, MIME and a source fingerprint. Client and service independently verify `infra/parser/service.lock.json` against the parser modules, isolation controls, Dockerfile and hash-locked requirements. A mismatch fails closed. The worker validates the returned block schema and original digest/MIME. Socket-mode checkpoints identify the implementation as `source-sha256:<fingerprint>`; host-mode checkpoints retain their immutable Docker image ID. This is build/source identity over a trusted private mount, not remote attestation. The built image ID is recorded separately in `service-build.lock.json` for local verification and scanning.

## Integration contract

Build `infra/parser/Dockerfile.service` using the repository root or the curated helper `infra/parser/build_service.py`. Compose must set `network_mode: none`, `ipc: none`, `read_only: true`, `user: "0:0"`, `cap_drop: [ALL]`, `cap_add: [SETUID, SETGID]`, `security_opt: [no-new-privileges:true]`, the resource limits above, and tmpfs `/tmp` with `mode=0700,noexec,nosuid,nodev`. The sole shared volume is `/run/parser`, writable for the supervisor and read-only for ingestion. No other credentials or volumes belong in this service.

Ingestion sets `ED_PARSER_SOCKET_PATH=/run/parser/parser.sock` and optionally `ED_PARSER_SERVICE_LOCK=infra/parser/service.lock.json`. The application image includes the new service lock and Dockerfile alongside existing parser requirements. API/worker code remains in the shared application image but only ingestion receives the socket. Health uses the same private protocol with a three-second timeout; sufficient retries tolerate a single60s extraction because the service is intentionally sequential.

## Tradeoffs and validation

Each document gets a fresh process but shares the service's container namespaces with its supervisor, unlike the original fresh-container model. A Linux kernel vulnerability remains outside these application guarantees. The UID/descriptor/filesystem/filter boundaries therefore need real-container regression tests. One service serializes extraction; additional isolated service/worker pairs can scale it if measured ingestion throughput requires that. Do not silently enable additional child syscalls when adding a parser library; review the new need and rerun boundary tests. No OCR, network downloader or native helper command is enabled.

`tests/integration/ingestion/test_parser_service.py` exercises ten actual golden formats through the service, container configuration, kernel denials for IPv4/Unix sockets and subprocesses, forbidden writes/shared memory, UID/capability/no-new-privileges limits, inaccessible supervisor/peer files, invalid hashes/envelopes/fingerprints, and cancellation after observing a real UID65532 child. Unit tests exercise bounded decoding and client rejection of wrong identity, huge/truncated/trailing responses and deadline failures. Host sandbox regression tests remain separate. The first live verification platform is Linux/amd64; aarch64 kernel execution remains unverified.
