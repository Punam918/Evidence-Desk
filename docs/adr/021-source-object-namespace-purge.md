# ADR021: Source object namespace purge with surviving receipts

Accepted implementation refinement,2026-10-12, within T28. `source-objects-purge --workspace UUID` erases storage content for deleted documents independently of later PostgreSQL source-row deletion. It requires the ordinary application database role and scoped object storage credentials; no identity, model, checkpoint, dispatcher or Qdrant credentials are used.

The worker selects one deleted document or a due `document_objects` tombstone, records that tombstone before external I/O, and fences unfinished ingestion jobs. Its object prefix is constructed exclusively from workspace/document UUIDs: `workspaces/W/documents/D/`. All revisions of a deleted document share this ownership boundary, including reprocessed revisions referencing an older original. Originals, parsed blocks, vector artifacts and uncommitted staging objects below that prefix can be erased without trusting arbitrary stored keys. Other document namespaces remain untouched. Live document rows override inconsistent receipts and fail closed.

Each invocation lists at most100 objects, rechecks tombstone authority before each delete, and verifies the namespace with another listing. Only a successful empty listing records `purged_at`. Partial deletion, storage errors and receipt-transaction failures remain retryable. No SQL transaction spans storage I/O. The operation has a30-second deadline; already issued synchronous storage calls can finish after cancellation, but remain constrained to the same deleted namespace. Return counts describe this page, not completion of the entire knowledge-base deletion.

Receipts remain due again after1 hour to remove delayed ingestion writes. They have no workspace/document FK and therefore survive later parent cascades; the scope remains derivable from their UUIDs. A receipt is an observation of an empty current namespace, not proof that a previously issued external write cannot arrive later. The future physical source/workspace purge must ensure every document has such a receipt before dropping its ownership row. The independent off-host deletion log and restore replay still need implementation.

This worker supports unversioned buckets only. It checks `GetBucketVersioning` before any work and refuses both Enabled and Suspended status: ordinary DeleteObject could otherwise leave historical versions. Operators must grant configuration-read, list and delete access and keep bucket versioning disabled throughout cleanup. Backup copies have their separate retention/deletion-log policy; this command does not erase backups. A future version-aware implementation requires explicit version inventory and deletion semantics.

PostgreSQL chunks/document titles and Qdrant manifest/outbox anchors remain for their separate cleanup and reconciliation. Source-derived answer redaction remains a separate scoped sweep and must finish before source rows are removed. Parent KB/workspace purge jobs are not marked complete by this command. Fleet scheduling, purge-age alerts, removal of ownership anchors and independent disaster recovery remain open.
