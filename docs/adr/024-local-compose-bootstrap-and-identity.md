# ADR024 — Self-contained local Compose bootstrap

Status: accepted for implementation,2026-10-19. Integrated startup validation is in progress. This changes local packaging, not tenant authorization or production readiness gates.

The required portfolio installation must include generation, ingestion, identity and storage without a hosted account. Root `compose.yaml` now defines the application and supporting services. Local generation remains the existing pinned Ollama/Qwen binding; embeddings, sparse encoder, reranker and tokenizers retain their artifact locks. Hosted credentials are optional and absent from the default deployment.

One offline init job creates random persistent credentials, a local CA/HTTPS certificate, identity import and storage configuration. It mounts the complete private secrets volume; serving processes receive only role-specific subpaths. No secrets are image build arguments, Compose environment literals, source files or bootstrap output. Existing values are retained; inconsistent files fail initialization rather than silently rotating identity. Database setup holds an advisory lock, runs business/saver migrations and provisions separate runtime roles plus a Keycloak-only database owner. Runtime roles cannot own application or checkpoint relations or bypass RLS.

The fixed local origin is `https://evidencedesk.localhost:8443`. Browsers resolve `.localhost` to loopback; Docker resolves the same name to Caddy through its backend network alias. The API trusts only the generated public CA file for the configured issuer. Caddy terminates TLS and proxies the realm endpoints to Keycloak's `/identity` path. The realm uses a confidential authorization-code client with PKCE S256, exact callback and a generated local demo password. Identity admin routes are not proxied. Installing the CA into the user's browser/OS trust store is an explicit operator action; bootstrap never modifies host trust. Public deployments need their own domain, issuer and trusted certificate.

Private objects use digest-pinned SeaweedFS4.48 with persistent filer/volume data, S3 authentication and an application identity restricted to the single application bucket. Filer/master/raw-volume interfaces bind container loopback; only authenticated S3 binds the private network. The initialization job checks unversioned storage, immutable conditional writes, round-trip data and anonymous-access denial before enabling uploads. This replaces test emulation for local runtime; test fixtures can continue using Moto. SeaweedFS single-host persistence is not an HA or backup guarantee.

Only Caddy's8443 is published, on127.0.0.1. PostgreSQL, Qdrant, objects, identity and application workers remain on an internal network. Model initialization/Ollama additionally have a download network for pinned public artifacts. Parser execution has no network and follows its separate isolation ADR. Runtime images use read-only filesystems and nonroot identities where supported; the parser supervisor has only the two capabilities required to demote child processes. No container mounts the host Docker socket.

Bootstrap and model downloads are separate jobs with completion dependencies. API browsing does not depend on the model downloading or passing readiness, so users can still manage a workspace during an inference outage. Model availability continues to require recorded, configuration/endpoint-bound native probes. Normal down/up keeps volumes. Removing volumes is a separate destructive reset, never an automatic migration fallback.

Evidence must include fresh startup, retained-volume restart, real OIDC login, storage/index/parsing integration and native local generation before T30 is complete. Final UI/media/README remain T31. Resource ceilings are configuration, not measured capacity; existing security, lifecycle and human-review gates remain open.
