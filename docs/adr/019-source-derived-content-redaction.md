# ADR019: Source-derived content redaction

Accepted implementation refinement,2026-10-12, within T28's deletion contract. Access checks already hide answers whose sources or history ancestry are revoked. The `source-redact` operator command additionally removes their stored generated content. It needs only the nonowner application database role with an explicit workspace scope; it returns counts, never private content.

Each invocation processes one terminal run in a10-second transaction. Selection requires a deleted workspace, a deleted directly referenced document/knowledge base, an explicit document tombstone, or a previously redacted parent referenced by the frozen prompt/rewrite/summary history IDs. Parent links are constrained to the same workspace, user and conversation. Independent knowledge/conversations are not selected. This is a fixed-point sweep: drain all pages, then schedule later passes for runs that were still active. Active runs remain subject to existing tombstone/cancellation/egress checks and must terminalize before their stored state is scrubbed. The future physical source purge must drain this work before removing source rows needed to resolve KB ownership.

Under admission/workspace locks, pending run jobs are fenced and reservations conservatively settled. `runs.execution_metadata.source_redacted=true` permanently marks the answer unavailable; `source_redaction_pending=true` keeps a partially drained run selected until cleanup finishes. Existing source/history checks now reject marked or missing runs before hydrating their answer. Reintroducing a source does not resurrect erased answers. These are internal metadata fields; there is no new public schema or alternate permissions mechanism.

The transaction clears the assistant message text/answer/citation titles, stored provider response/request hash, conversation summary and associated feedback. Events, tool proposal arguments/results and saved brief content are removed or scrubbed in100-row pages. Pending effects become failed, and mapped threads become terminal/expired for the existing checkpoint retention command. Brief rows retain their identity but are displayed as unavailable with no answer/citations. User-authored queries and titles, source-reference IDs/hashes and aggregate accounting remain; no text classifier guesses whether a user independently typed similar text.

The source flag, content mutations and pending-page marker commit together, so failures roll back a whole page. Read-time ancestry checks hide descendants immediately; repeated sweeps also erase their stored generated content. A marked parent remains available as an ID-only dependency until conversation retention removes that conversation, whose history cannot be shared with another conversation.

This command is not the physical source/object purge worker or a timed-retention scheduler. Original objects, chunks/vector artifacts and Qdrant points still require their own deletion lifecycle. Fleet supervision, independent deletion-log backup/replay and the restore drill remain unfinished. Candidate discovery scans scoped provenance; T29 must measure its load behavior before claiming production scale.
