# Qdrant index ownership, publication and recovery

Normative v2 design. PostgreSQL is permission/content truth; Qdrant is a derived search index; private object storage retains immutable source and vector artifacts for rebuilding. The system has no cross-store transaction. [Config](../../contracts/config/qdrant.yaml), [point payload schema](../../contracts/schemas/qdrant-payload.schema.json), [SQL](schema.sql) and [retrieval](../03-ai-engineering/retrieval.md) must agree.

## Collections, point format and scope

One physical collection per immutable embedding+sparse profile generation (`ed_bge384_bm25_v1_<config-hash-prefix>`), shared across workspaces. Concrete collection names are stored in index_manifests; do not route an in-flight read via a mutable global alias. Collection contains named dense384/Cosine and sparse BM25/IDF vectors. On-disk vectors/payload/sparse index reduce resident footprint but do not guarantee RAM usage. Single demo replica is not HA. No quantization initially; compare exact filtered search before changing HNSW/quantization.

Point ID equals globally unique server-generated chunk UUID. Payload: workspace_id, kb_id, document_id, revision_id, profile_id, text_sha256, manifest_sha256. No text, filenames, user identities, object URLs, approvals or active-boolean authorization shortcuts. Index workspace_id as tenant-aware keyword and KB/document/revision/profile as keyword before inserting points. The payload schema validates UUID/hash fields; dimensions and sparse numerical invariants are validated separately.

Every search branch receives a server-built filter from authorized PostgreSQL revisions. Strict mode denies unindexed filter keys; it does **not** require the caller to include a tenant filter. Only Retriever can call the read client, and its interface requires AuthContext+ResolvedScope; unfiltered query APIs are not exposed. Read-only key and write key are separate, private network, TLS across hosts, no browser access. Qdrant cannot enforce PostgreSQL RLS. Candidate hydration and a final authority check are mandatory even if payload filters succeeded. Raw similarity scores and global IDF statistics are not public endpoints.

The sparse encoder uses FastEmbed BM25; collection IDF statistics include staging, superseded and other-tenant points. Filtering limits returned points, not those statistics. This is an explicit relevance-coupling limitation. Freeze all collection contents for evaluations and record corpus generation. Stronger statistical isolation needs per-tenant collection review; do not claim tenant-local BM25. Retaining old revisions for comparison makes that caveat material.

## Publication protocol

1. Authorized upload creates immutable revision + job transactionally. Parse/normalize/chunk and embed under job lease; vectors are written to a private immutable artifact manifest with exact point IDs, dense/sparse profile hashes and per-chunk hashes. PostgreSQL stores authoritative chunks. SHA256 covers a canonical sorted manifest excluding its own manifest_sha256 field; artifact key belongs to the workspace/revision namespace.
2. In one fenced PostgreSQL transaction create index_manifests(state=staged, expected_points, artifact_key, manifest_sha256, collection_name) and one outbox `upsert` operation keyed by revision/profile/manifest hash. No raw vectors in SQL. Create collection/indexes at provisioning, not from arbitrary upload parameters.
3. Outbox worker claims a30s lease with monotonic token; heartbeat10s; batch≤100 operations. Before every vector batch recheck tombstones and immutable manifest. Upsert deterministic point IDs, `wait=true`, `ordering=strong`, bounded3 retries. A lost acknowledgement is uncertain, not absent; retry identical content. Strong ordering is a Qdrant property, not a distributed PostgreSQL commit or exactly-once guarantee.
4. After all writes, exact filtered count plus paginated point-ID/hash verification against manifest must pass. Missing/extra/wrong-hash points fail verification; do not publish based only on HTTP200 or optimizer completion. Set manifest verified and outbox done in a fenced DB transaction; store timestamp and count. Wake ingestion finalization, which reacquires its own job lease before publication. Dense/sparse presence, dimensions and every vector value are checked by paginated readback (float tolerance1e-5); corrupted artifact hash is a permanent integrity error.
5. Ingestion finalizer (not the outbox delivery worker) locks document and revision in PostgreSQL under its renewed job lease. Require verified manifest, matching active profile/collection, unchanged document version, live KB/document/workspace and latest requested revision. Set former active revision superseded, publish new revision, swap active_revision_id and increment corpus generation atomically. Mark ingestion job succeeded in the same publication commit. Competing older upload cannot overwrite latest desired revision; keep it unexposed and reconcile. Qdrant already has the points; authorized revision filters make the pointer swap effective without rewriting every payload.

Crash windows: before upsert→pending retry; after upsert before verification→verify/retry same points; after verification before pointer→old active remains; after verified outbox completion before ingestion finalizer→resume finalizer; after publication commit before worker acknowledgement→observe succeeded job/published manifest; Qdrant lost after publication→retrieval unavailable/rebuild, never silently mark document empty. No vector store availability guarantee follows from a verified historical count.

## Outbox and deletion

index_outbox owns delivery progress/lease only; ingestion jobs own parsing/embedding. Poll500ms, reconcile60s, max3 transient delivery attempts before dead+alert; user ingestion retry or operator repair resets authorized retry state. Do not run two independent job and outbox lease owners for the same vector side effect. SQL outbox payload is only references to manifest; dispatch can use privileged bounded claiming routine but all content access remains workspace-scoped. Expired claims require new fencing token for DB writes. External Qdrant cannot enforce that token: stale upserts are handled by immutable IDs and tombstone fencing in PostgreSQL, then reconciliation.

Delete transaction first commits parent tombstone, revokes new reads/replays and enqueues purge for every collection/profile generation. Delete points by exact workspace+revision filter with wait=true; exact count0 confirms; mark purged and delete derived vector artifact/text/checkpoints under retention policy. Retain compact tombstone and index manifest/outbox metadata until retry windows expire and deletion is verified; don't cascade them away first. Any delayed upsert after purge can physically resurrect an orphan point; PostgreSQL prevents disclosure, and repeated tombstone reconciliation deletes it again. Alert on purge older24h. This design promises immediate authorization fencing, not instant physical erasure of an in-flight external write.

## Reconciliation and restore

Reconciler compares pending/dead outbox rows, verified manifests, live active revisions and Qdrant counts/checksums; full manifest audit daily, bounded checks every60s. Missing/corrupt published index is marked unavailable and rebuilt from immutable artifact; no new generation call uses partial evidence while rebuilding. Unknown points are orphan-quarantined then deleted after verifying they belong to no live manifest. Superseded published revisions remain searchable only in explicit compare until parent deletion or documented retention policy.

Back up PostgreSQL including ownership mappings/checkpoint schema, private objects/artifacts and optional Qdrant collection snapshots with manifest hashes. A snapshot speeds restore but is not the authority. Restore while admission closed: PostgreSQL→objects→tombstone replay→snapshot restore or full derived-index rebuild→full manifest verification→tenant/compare/delete smoke→readiness. Snapshot freshness may differ from DB, so always reconcile. No active revision serves until its manifest is verified against restored Qdrant. Document RPO24h/RTO4h as measured targets; rebuilding100k points may miss RTO and must be timed.

Profile change builds a new immutable collection and all replacement manifests; queued writes are paused or dual-built during final catch-up. Only switch a workspace profile/revision generation transaction when all live documents are verified. Keep old artifacts7d for tested rollback; tombstones apply to both collections. Destroy old collection only when no live manifest/citation comparison references it and grace has elapsed.

## Acceptance and source basis

INDEX-RECOVERY exercises stage invisibility, wrong tenant, incomplete vectors, uncertain acknowledgement, competing publication, stale upsert after tombstone, collection loss and stale restore. RET-RANK compares exact/ANN and dense/sparse/fusion/reranking on frozen authorized data. Official [multitenancy](https://qdrant.tech/documentation/manage-data/multitenancy/) and [hybrid query](https://qdrant.tech/documentation/search/hybrid-queries/) docs establish supported mechanisms; the consistency protocol above is this project's design, not a vendor guarantee.

## Implemented T14 boundary

`ingestion/publish.py`, `workers/index.py` and the scoped repositories implement the protocol. Publication also checks an ordered ID/ordinal/text-hash digest and recomputes authoritative chunk text hashes inside its final transaction. Readback compares every payload and dense/sparse vector. Outbox retry delays use2/8/30-second bases with20% jitter, at most3 claims; explicit ingestion retry resets an exhausted upsert. An internal repair of an already published immutable index can proceed after the original uploader leaves; new unpublished ingestion still requires that actor's live editor permission, and user reads always reauthorize.

`lifecycle/reconcile.py` offers bounded20-revision audit pages and100-point orphan pages. Full audits verify both the original source and the canonical vector artifact, mark broken indexes unavailable, and enqueue repair from the same frozen artifact. Collection loss rebuilds only the configured immutable generation. Normal audits do not reset dead delivery budgets. Unknown points are quarantined24h in `index_orphans`, then checked against global known chunk IDs and current payload before removal. A wrong-tenant payload on a known chunk is preserved for its owning manifest to repair; it is not an unknown orphan. Extra unknown points can keep exact verification unavailable until quarantine cleanup and an explicit repair.

Worker commands and scoped operator audit invocation are documented in [ingestion workers](../../infra/workers/README.md). The deployment scheduler must drain audit cursors every60s and complete a full daily pass; automatic fleet scheduling, physical object/text/checkpoint purge and the measured restore/admission drill remain T28/T30. There is no readiness or live retrieval claim until T15 connects its authorization and index-availability checks.
