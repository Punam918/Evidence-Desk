# Threat model and verification

Assets: private documents, conversations, session/provider credentials, tenant boundaries, model spend, source integrity and audit evidence. Actors: legitimate members, malicious member, unauthenticated attacker, poisoned source author, compromised dependency/provider, mistaken operator. Boundaries: browser↔API; API↔IdP; API/worker↔DB; uploads↔parser; evidence↔model; model/tool proposal↔authorized executor; operator↔deployment.

The [OWASP injection guidance](https://cheatsheetseries.owasp.org/cheatsheets/LLM_Prompt_Injection_Prevention_Cheat_Sheet.html) motivates layered checks; instructions alone cannot enforce permissions. The [upload guidance](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html) motivates format validation and isolation. The table below is the project's own concrete threat model, not a claim of OWASP certification.

|---|---|---|---|---|

## Operational controls

TLS public endpoints; encrypted disks/objects/backups with managed key or separately stored age recipient. API credentials are environment secret file mounts, never committed .env or browser config. Separate migration/runtime/identity/dispatcher roles. DB/object/model ports private; firewall public80/443 only, SSH restricted to operator identity. Network policy denies parser egress entirely. Worker may reach only DB, object endpoint and configured providers.

Data classification: synthetic/public fixture corpus for public demo; confidential documents require explicit workspace processing policy and provider data-terms review. Do not claim local-only merely because frontend is local: embeddings, rewrites, summaries, judges and hosted GPU all count as processing. Paid-provider fallback is prohibited for local-only. No sensitive production data in evaluation exports by default.

Audit actions: login/logout, membership/settings change, document upload/reprocess/delete, job retry, model route/fallback, tool propose/approve/execute, budget denial, evaluation import and restore. Store actor/target/time/request/hash/status; exclude raw content. Audit updates/deletes denied to runtime role; retention worker has separate grant. Operators can tamper with their own database; cryptographic external audit anchoring is future hardening, not claimed.

Release gate: SEC-AUTH, SEC-TENANT, SEC-UPLOAD, SEC-INJECTION, SEC-EGRESS, SEC-RENDER, SEC-TOOL, SEC-LOGS, SEC-SUPPLY all pass; critical/high unresolved exploitable issues block public deployment. Low-risk dependency finding exceptions need owner/date/reason/expiry in risk register, not silent suppression.

## Qdrant and checkpoint additions

Qdrant credentials are server-only; separate read/write keys and private network/TLS. Every dense/sparse query uses authorized workspace/KB/revision/profile filters and PG hydration; strict mode is not authorization. Poisoned point payload can never supply prompt text. Stage and superseded points need explicit eligibility, tombstones veto stale results. Collection-level IDF can couple tenant ranking; no public raw-score endpoint, and stricter statistical isolation requires separate collection policy.

No generic graph/thread/checkpoint API. Creator-scoped thread mapping and current authorization are mandatory on resume; forged UUID/hash/decision is not approval. JSON-only checkpoint codec rejects arbitrary object reconstruction/pickle. State contains IDs/hashes only; no credentials or hidden reasoning. Dedicated saver role/schema, content-free default telemetry, bounded retention and deletion cover metadata leaks. Provider response ledger is confidential content and is purged with its sources. Security tests include foreign thread replay, checkpoint tampering, source deletion during interrupt and stale Qdrant upsert after purge.

T17 recovery boundary: an immutable creator-private prompt manifest binds ordered source/history IDs and hashes to the exact model/schema/request fingerprint before any attempt. Stored complete responses may replay validation; issued or ambiguous attempts never replay generation. Source hashes, current policy and selected-history dependencies are checked before egress and finalization. Provider JSON is buffered and strict-parsed; the UI receives only validated sentence strings, never arbitrary provider fields. Readiness reports bind the operator endpoint as well as model configuration. No endpoint is selected by user/model text. Prompt quoting and citation membership checks do not prove semantic truth or comprehensive injection resistance.

T18 evidence reads accept only published/superseded revisions under live workspace membership and document/knowledge-base tombstone checks. The original attachment proxy copies at most the authoritative size (20 MiB maximum) to a private temporary file, verifies SHA256, rechecks access before headers, then rechecks before each 64 KiB response chunk. No transaction spans object/network I/O. Revocation after headers terminates the response instead of returning a partial file as a successful download; Content-Length exposes truncation to the fetch client. Previously delivered bytes and one already-authorized in-flight chunk cannot be recalled. Originals always use application/octet-stream, attachment disposition, nosniff and no-store; no public or signed object URL is returned. Control/bidi/path syntax is removed from the encoded display filename. Temporary files are cleaned on completion/cancellation; a cancelled copy is joined before cleanup.

T21 auxiliary-memory boundary: model output cannot choose source scope, endpoint, roles or tools. Rewrite and summary schemas are fixed and bounded; source/history IDs are checked against the server snapshot, and quoted history never becomes system policy. Request purpose separates auxiliary results from final answer recovery. All calls share the run budget and uncertain transport never retries. Stored summary/rewrite history dependencies are revalidated through the same bounded ancestry traversal before later disclosure. Production serving and automatic scheduling remain off pending paired evaluation.

2026-10-19 reliability hardening: ADR022 adds deterministic output quotation/citation-label/display validation and stronger optional rewrite literal checks. Native scripted-provider fixtures place attacks in published source text, document titles and private history and verify that attempted schema extensions/unknown citations produce no draft or tool effect. These are application-boundary tests, not a measured live-model attack success rate. Source snapshots include prompt .txt files to prevent prompt-only evaluation provenance drift.
