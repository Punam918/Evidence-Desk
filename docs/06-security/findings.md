## Supply-chain evidence

It exits nonzero for unresolved high/critical image occurrences, application dependency advisories, credential findings, skipped unaudited packages, tool failures, empty analyses or lock changes during the audit. No ignore list suppresses container vulnerabilities. Only locally available locked images are scanned; missing images fail the gate instead of silently changing versions.

Gitleaks initially reported54 generic-key matches. Inspection showed public tokenizer artifact SHA256 fields and paired synthetic `keys-NN` source identifiers. Generated/dependency caches, private mounted secrets and the scanner's own generated reports are explicitly outside the distributable-source scan. This does not establish that local private secret storage is correctly provisioned. Scanner archives and binaries are pinned in [tools.lock.json](../../infra/security/tools.lock.json); matching a published checksum is integrity evidence, not signed build provenance.
