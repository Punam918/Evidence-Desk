# Organization chatbot reliability review

Researched2026-10-19 at the user's request. Scope: EvidenceDesk's shared organization knowledge bases, private conversations and bounded approved tools. This is an engineering review of primary sources and the repository, not a systematic literature review or a claim to cover every published technique. New research does not establish superiority on this project's corpus. No live benchmark or new human labels were produced by this review.

## Findings and project decisions

| Failure mode | Evidence and applicable technique | Repository assessment / action |
|---|---|---|
| Relevant retrieval still cannot answer the question | Separate context sufficiency from model ability; evaluate abstention and answer coverage. [Sufficient Context](https://arxiv.org/abs/2411.06037) | Empty-context abstention exists. Add selective-answer evaluation; do not interpret cosine/RRF/logits as probabilities or deploy an arbitrary threshold. |
| Valid citations do not imply supported claims | Citation correctness and faithfulness are distinct. [Attribution study](https://arxiv.org/abs/2412.18004) | Existing E-label validation proves membership only. Add deterministic quotation verification; retain human claim/citation review and explicit semantic limitations. |
| Conflicting sources or parametric-memory override | Measure conflicts and abstention together. The2026 SABER preprint studies a trained approach, not a drop-in prompt guarantee. [Trust or Abstain?](https://arxiv.org/abs/2605.18792) | Strengthen conflict/scope prompt, preserve both comparison sides and evaluate conflict fixtures. Do not claim SABER implemented or invent a trained verifier. |
| Missing exact codes/names | Dense+sparse candidate retrieval and rank fusion. [Qdrant hybrid queries](https://qdrant.tech/documentation/search/hybrid-queries/) | Already implemented with authorized hydration. Preserve codes, signed numbers, percentages, quotations and polarity when rewriting. |
| Chunks lose document context | Contextual embeddings/BM25 and reranking can improve retrieval on measured corpora. [Contextual Retrieval](https://www.anthropic.com/engineering/contextual-retrieval) | Heading/table context and reranking exist. Generated contextualization needs a new immutable profile/index and an ablation before promotion; source text must remain original. |
| Excess context distracts the model | Finite context budgets, deliberate selection and memory management. [Context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents), [Lost in the Middle](https://aclanthology.org/2024.tacl-1.9/) | Whole-passage packing, deduplication, token accounting and bounded recent history exist. Add position/distractor evaluation; do not increase context blindly. |
| Pronoun rewriting changes the question | Literal guards cannot prove semantics, but can reject observable corruption | Optional rewrite already preserves scope. Extend checks to contractions, introduced negation, signed quantities, percentages, identifiers and quoted literals. Keep original on rejection. |
| Summary becomes invented knowledge | Reference-bound memory with current source checks | Existing summary provenance and ancestry checks; generated summaries remain experiments. Prior assistant messages are not evidence. |
| Direct/indirect prompt injection | Separate instructions/data, constrain capabilities, validate outputs and use layered testing. [OWASP injection guidance](https://cheatsheetseries.owasp.org/cheatsheets/LLM_Prompt_Injection_Prevention_Cheat_Sheet.html) | Quoting, external authorization and no arbitrary execution already exist. Strengthen poisoned-carrier tests. Regex/classifier filtering alone must never authorize a request. |
| Poisoned corpus, stale index or revoked access | Secure the entire ingestion/retrieval/cache/deletion pipeline. [OWASP RAG guidance](https://cheatsheetseries.owasp.org/cheatsheets/RAG_Security_Cheat_Sheet.html) | Immutable artifacts, tenant filters, hydration and revocation checks exist. Physical PG source/workspace deletion and independent restore logs remain open T28 work. |
| Tool misuse and repeated side effects | Restrict functionality/permissions and verify approved effects. [OWASP excessive agency](https://owasp.github.io/www-project-top-10-for-large-language-model-applications/2_0_vulns/LLM06_ExcessiveAgency.html) | Separate brief approval graph, live authorization, payload hash and idempotent DB effect exist. No model-authorized tool or general shell/browser needed. |
| Output exfiltration or misleading rendering | Treat model output as untrusted | Plain-text rendering/no remote images already exist. Add server rejection of fabricated inline labels and bidi/control manipulation; natural RTL text stays supported. |
| Latency, runaway retries and ambiguous billing | Bounded workflows, budgeted attempts and explicit uncertain outcomes | Existing deadlines, reservations, breakers and no blind repeat after issued requests. Measure end-user latency/load; retain T29 work. |
| Averages hide failures, easy examples or evaluator bias | Combine deterministic checks, reviewed rubric judgments and representative task evaluations. [Agent evaluation engineering](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents) | Existing hash-bound evaluation and review tooling. Add risk/coverage diagnostics with unknown-label bounds; no fabricated reviews or excluded failed attempts. |
| Cross-document/global questions | Graph summaries can address different query patterns. [Microsoft GraphRAG](https://microsoft.github.io/graphrag/) | Candidate experiment for corpus-wide/global queries, not a default replacement. Requires measured demand, extraction cost, source-level permissions and deletion propagation. |
| Non-English retrieval or language mismatch | Evaluate languages explicitly; English performance does not transfer automatically. [XRAG](https://arxiv.org/abs/2505.10089), [MEMERAG](https://arxiv.org/abs/2502.17163) | Current BGE-small profile is English. A multilingual profile requires a separately hashed model/index and reviewed multilingual fixtures. Do not advertise multilingual retrieval quality from Unicode support. |
| Tables, scans and diagrams lose meaning | Evaluate ingestion coverage as well as generation. [Multimodal RAG benchmark](https://arxiv.org/abs/2502.17297) | Table context exists; OCR/image understanding is not implemented. Add these only with source-coordinate preservation, parser isolation and evaluation cases. |
| Multi-agent complexity adds failure/cost | Start with bounded workflows; expand when task evidence supports it. [Building effective agents](https://www.anthropic.com/engineering/building-effective-agents) | Retain LangGraph's bounded workflow. Autonomous agent teams are not needed for ordinary organization policy Q&A. |
| Unrepresentative enterprise benchmark | Test actual query distributions and realistic source content. [WixQA](https://arxiv.org/abs/2505.08643) | Existing synthetic dataset has only8 archetypes and0 human reviews. Organizational corpus review remains necessary; external benchmark scores cannot certify this deployment. |
| Dependency/service changes break reliability | Immutable releases, conformance probes, vulnerability review and restore rehearsals | Existing locks/scans/probes. Previously recorded image advisory gate is still unresolved; a dated scan must be refreshed before release, not assumed current. |

## Implementation order and acceptance

1. Deterministic output integrity and versioned conflict/sufficiency instructions: exact quotations checked only against the sentence's cited source text; labels rendered by application; reject unsafe display controls. Test through native graph before drafts and completion. This does not verify paraphrase entailment.
2. Follow-up rewrite safeguards: preserve literal constraints and reject altered polarity/identifiers; exercise real optional rewrite transport/accounting. No automatic serving promotion of the rewrite experiment.
3. Selective answering diagnostics: planned denominators, separate failures/missing/unscored/native abstention/withheld answers, human-review coverage, tied scores and explicit unknown risk bounds. No held-out threshold selection or self-confidence-as-truth.
4. Carrier-aware adversarial and context sensitivity evaluation: retrieved content, titles, conversation history, unavailable facts, contradiction and missing evidence; record scripted versus live-model evidence separately.
5. Continue unresolved production lifecycle, security remediation, CI/load, reviewed evaluation and restore gates. These are reliability features, not optional portfolio polish.
6. Evaluate contextual retrieval, multilingual models, hierarchical/graph retrieval, OCR and learned sufficiency/entailment only against representative reviewed cases and CPU/latency/privacy budgets. These are candidates, not features silently enabled or claimed implemented.

Adding all competing techniques simultaneously would make attribution, costs and failure diagnosis worse. Each selected method needs a measured acceptance gate. The repository's implementation tracker records concrete additions and outstanding work in [reliability status](../../tasks/reliability-status.json); the original backlog remains in force.

## Tool choices and product breadth

The user delegated the KB focus to engineering judgment. Prioritize a configurable organization assistant evaluated on policies, technical documentation and support knowledge. Do not advertise equal competence across every domain, language or document modality. Keep the existing tenant/private-chat boundaries for all three use cases.

These are project decisions inferred from the research and current acceptance gaps, not vendor recommendations or measured comparisons:

| Tool/method | Capability reviewed | Decision |
|---|---|---|
| Ragas | Retrieval, faithfulness, noise-sensitivity and agent metrics; some use LLM calls. [Official metrics](https://docs.ragas.io/en/latest/concepts/metrics/available_metrics/) | Candidate supplemental judge after calibration against human labels and privacy/cost controls. Existing exact-span and human-review runners remain authoritative; not installed by this change. |
| NVIDIA NeMo Guardrails | Configurable input/output checks, including content safety, jailbreak detection, topic control and PII handling. [Official overview](https://docs.nvidia.com/nemo/guardrails/latest/home) | Candidate for a demonstrated classification need. Classifier decisions cannot replace database authorization or tool approval; not integrated by this change. |
| DSPy optimizers | Optimize programs against examples and a defined metric. [Official optimizer guidance](https://dspy.ai/3.4.1/diving-deeper/choosing-an-optimizer/) | Requires reviewed development examples, a useful metric and an explicit tuning budget. No automatic prompt optimization before those exist. |
| Existing Qdrant/LangGraph/Pydantic stack | Hybrid retrieval, bounded durable workflows and strict output schemas already implemented | Preserve core architecture and dependency locks. This review adds safeguards and evaluation code, not an unverified framework migration. |

Implemented evidence is summarized in the [reliability hardening report](../10-testing/reliability-hardening-report.md). The [context diagnostic](../07-evaluation/context-sensitivity.md) measures actual packing behavior across54 synthetic topic/variant/tokenizer combinations. It does not measure live semantic quality.
