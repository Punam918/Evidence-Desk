# HTTP and session contract

The [OpenAPI 3.1 document](../../contracts/openapi.yaml) defines 52 operations. Each operation has role, rate, schemas, statuses and examples. OpenAPI examples illustrate shape; semantic cross-field rules here are mandatory. API responses contain UUIDs and ISO UTC times; requests reject unknown fields. Public version prefix `/v1`; backward-incompatible changes require `/v2` or a reviewed migration plan.

## Authentication and authorization

Browser uses same-origin opaque `ed_session` Secure, HttpOnly, SameSite=Lax, Path=/ cookie. OIDC authorization code + PKCE S256 handled by backend, state/nonce random 256-bit, single use, 5min expiry. Validate discovery issuer, audience, signature with allowlisted algorithm, nonce and timestamps, never tokens from query beyond callback code. Store hashed session ID and CSRF token hash; idle expiry 8h, absolute 24h (`expires_at` absolute, `last_seen_at` updated at most once per5min). Rotate after login or role-sensitive session change. `/v1/me` returns CSRF token in JSON; API requires exact `Origin` and token for mutations. `/auth/logout` revokes cookie/session and clears client caches. No own password/login reset implementation.

Login callback state cookie binds initiating browser; reject callback if missing or mismatched. Relative return path allowlist `/`, `/workspaces/*`; reject scheme-relative `//`, encoded traversal and arbitrary origins. Keycloak dev realm, managed standards-compliant OIDC public deployment. Verified email is for adding existing users; OIDC `(issuer,subject)` is identity. Case-normalize email for lookup; reject conflicting verified identities until reviewed, never auto-link solely on unverified email.

Membership roles: viewer reads shared KB/docs and own chat; editor adds/reprocesses documents and saves own briefs; admin adds deletion/settings/aggregate health/evals; owner adds membership/workspace deletion. All can create a workspace (operator quota 5/user). Last-owner protection uses workspace row lock. Foreign workspace/object UUID returns 404 even if valid elsewhere. Known object within own scope with insufficient action role returns 403. Private conversation owner check applies to all roles. No service bypass accessible through a request field.

## Idempotency, versions and pagination

All authenticated POSTs require Idempotency-Key (16–128 chars); scope `(actor, workspace or global, method+normalized route, key hash)`, validity 24h. Workspace creation/logout need global identity-scoped idempotency storage (see backend design). Hash canonical JSON or streamed upload digest plus MIME/name. Same key/body returns original status/body; changed body 409. Concurrent first submissions serialize and one wins. Cached response must pass **current** authorization/tombstone checks before replay; do not replay deleted source content. PUT feedback is naturally idempotent; PATCH uses expected_version. Missing/mismatched version 422/409 respectively.

Collections use opaque HMAC-signed base64url cursor binding actor/workspace/resource/filter/sort and last tuple. Default limit20 max100, ascending `(created_at,id)` except conversations `(updated_at DESC,id)` and messages `(sequence,id)`. Cursor must not be reused across workspaces. Snapshot consistency across separate pages is not promised; clients deduplicate IDs. No raw SQL offsets or unsigned IDs as cursors. Empty page `{items:[],next_cursor:null}`.

Errors use `application/problem+json`: type stable problem URL, title, HTTP status, code, safe detail, request_id, retryable. No raw provider response, SQL, tokens or file paths. 400 malformed request; 401 missing/expired session; 403 action forbidden; 404 missing/foreign; 409 version/active run/hash/approval conflict; 413 limits; 422 valid JSON with invalid fields or semantic policy; 429 rate/budget; 503 dependency; stream expiry 410. HTTP 202 means enqueued, never success of ingestion/generation. Unexpected errors 500 with same Problem shape (implementation must include in generated contract).

## Rate/admission rules

120 requests/min/user default, mutations30/min; uploads10/min and 1 concurrent/user; run creation10/min, 2 running-or-queued slots/workspace, 5 global. DB atomic counters are baseline; edge IP limit 60 login requests/min for unauthenticated traffic. Queue depth cap100 ingestion jobs/deployment, 10/workspace; refuse new upload with 429 before storing large body if known full. Streaming opens max3/user and10/deployment; PostgreSQL session locks enforce these across API processes. Disconnect frees reader slots but run continues. The global cap bounds dedicated reader connections within the deployment DB budget. Budgets use UTC windows and 429 with next-window Retry-After; request cap denial needs user policy adjustment, not a blind retry loop.

## Semantic constraints and validation

Ask: nonempty kb_ids1–10, all same authorized workspace, revision_ids absent. Compare: exactly two distinct revision_ids, same workspace, within selected kb_ids, published/superseded only, live document. Query ≤2000 chars, ≤256 embedding tokens and ≤512 generation tokens. Unavailable explicit model 409. Settings budgets ≤operator ceilings, monthly budget ≥daily; retrieval profile rewrite requires enabled feature flag. Source download revision must belong to document. Brief proposal requires own completed answered message from specified run. Feedback only own final assistant message; abstentions may receive feedback.

Usage start/end inclusive UTC dates, maximum90 days; validate start≤end. Evaluation import is offline **aggregate** report import, not a user-triggered unlimited benchmark job; case-level artifacts remain local versioned files, case records can be imported by admin CLI using domain service. Reports must show failed case counts and metric denominators. Workspace deletion job remains owner-visible until purge; after deletion all workspace routes return404, so client can treat disappearance after accepted purge as deleted.

Source invalidation contract: Message/Brief `source_status=unavailable` returns `answer=null`, message text empty, and citations with available=false (no excerpt). State may remain final to preserve historical execution status; UI displays “Source removed; answer unavailable”. Purge removes content-bearing stored answer/text. This is distinct from a failed generation.

Conversation history includes `Message.run_id` only for its creator's assistant message. It is an opaque, creator-scoped handle for reopening an existing run, inspecting its terminal state, or beginning the already-authorized brief proposal flow; clients must not derive or guess it. A `Run` exposes its persisted `intent`. For a comparison run, `comparison` retains A/B order from the original request and rehydrates only currently authorized revision metadata. Removed, redacted, or otherwise unavailable sides contain the original opaque revision ID and `available=false`, while document/title/version fields are null. The browser must not persist comparison names or source content as a replacement.

Implemented usage windows include both start_date and end_date (1–90 UTC dates). `requests` counts ledger attempts, including outstanding reservations and definite failures; token totals sum only reported counts. `cost_micro_usd` sums settled/estimated charges and excludes reserved rows; `reserved_micro_usd` sums only outstanding reservations within the same scope/window. `estimated_attempts` counts rows marked usage_estimated/estimated, including zero-cost local unknown usage. No response/prompt/user identifiers enter the aggregate. More than1000 daily model buckets returns422 requiring a smaller window rather than silently truncating. Feedback upsert preserves updated_at when vote/reason are unchanged and rejects source-unavailable answers.
