# LangGraph workflow and checkpoint contracts

Normative v2 design. Use StateGraph with explicit nodes and conditional edges, PostgreSQL AsyncPostgresSaver and `durability="sync"`. PostgreSQL jobs retain queue/admission/leases. LangGraph owns graph progress; domain services own authorization, provider attempts, cost, final answers and effects. No hosted LangGraph service, generic agent loop or LangChain provider wrapper is required. See [graph contract](../../contracts/config/workflows.yaml) and [state schema](../../contracts/schemas/workflow-state.schema.json).

## Two separately owned graphs

`answer_v1`: START→authorize→route→retrieve→context→generate→validate→finalize→END. retrieve branches to abstain→finalize when no evidence; typed failures/cancellation go through terminalize. Intent compare uses the same graph with a bounded pair retriever and comparison prompt; original comparison read-call cap3 remains. An optional single rewrite is inside bounded retrieval, not a graph self-loop. At most16 node supersteps,60s active deadline and configured provider attempt limits. Graph errors cannot bypass terminal event/usage settlement.

`brief_v1`: START→prepare→approval→reauthorize→save→END. prepare resolves an existing creator-owned final answer into a frozen tool_executions record. approval calls `interrupt` with execution ID and payload hash only. It holds no job slot, transaction or SSE connection while waiting. Approval expires10min. Resume via Command(resume=...) uses the **same server-owned thread**, and reauthorization reads the already-recorded decision/current expiry/membership/role/sources; resume input itself grants nothing. The interrupted node may run again, so nothing before interrupt has a non-idempotent effect. Rejection/expiry terminalizes without saving.

A brief thread is distinct from the answer thread. A completed answer run and its event sequence never reopen for approval; existing proposal/approval REST endpoints return ToolExecution status. The answer stream has one terminal event. Tool status polling communicates proposed/awaiting_approval/approved/running/succeeded/failed/rejected/expired. No framework state endpoint is exposed.

## State and authority

Thread UUID is generated by server; app.workflow_threads maps it to workspace/user/run and optional tool execution, graph version, state schema version, expiry/status. Answer has one thread per run; brief one per tool execution. Caller never chooses thread_id, checkpoint namespace or checkpoint_id. Every inspect/resume operation resolves mapping under ordinary tenant/creator authorization, then reauthorizes live domain objects. UUID secrecy is not authorization.

Persist only primitive JSON: schema_version, thread_id, run_id, intent, revision_ids, evidence_chunk_ids, attempt_id, tool_execution_id, step and config_sha256. No raw messages, retrieved text, credentials, cookies, AuthContext, provider objects or hidden reasoning. Nodes hydrate authorized records just-in-time; source hashes/config versions bind saved references. Immutable schema/config checks reject malformed or incompatible state before execution. State fields are hints to progress, never permission claims.

Use an explicit versioned JSON envelope serializer implementing SerializerProtocol: domain state accepts primitives only; framework checkpoint envelopes additionally allow exactly LangGraph Interrupt (value/id, response_schema=None for these graphs) and built-in tuples. A live probe found that plain JSON cannot serialize the framework Interrupt object. Encode explicit reserved tags and validate exact fields/types on decode; never import a module/class named in stored bytes. Reject unknown tags/types, pickle, nonfinite floats, reserved tag keys in user dictionaries, depth>32 and payload>1MiB. These are serializer limits, not permission grants. Domain state independently validates against workflow-state.schema.json before nodes. Compatibility fixtures must cover every planned branch; unsupported framework values block the upgrade rather than enable arbitrary reconstruction. Encryption at rest through encrypted disk/backups remains mandatory. The probe codec is a synthetic validation helper, not a completed application security implementation.

## Persistence and concurrency

Provision dedicated lg_checkpoints schema owned by migration role; run supported AsyncPostgresSaver.setup in a release migration job once, never every API startup. Exact vendor tables/migrations are owned by pinned saver package; do not hand-maintain a guessed schema in business SQL. Runtime checkpoint role can access that schema only; API role cannot. Configure fixed search_path, psycopg autocommit/row factory as supported, separate pool from business transactions, and direct/session connections for advisory locks (not PgBouncer transaction pooling). Validate all of this with real saver in T01/T02.

A worker first claims a business job then acquires a session advisory lock keyed by thread UUID on a dedicated connection; hold until invocation exits. All graph invocations, including API-triggered brief resume and maintenance recovery, use that gate. A reclaimed lease alone does not authorize a concurrent graph invocation while old gate remains held; retry until holder exits. Healthy worker cancels graph on lease/heartbeat failure. Bounded active deadline prevents indefinite ownership; an unresponsive process is terminated operationally before lock takeover. No SQL transaction is held across network/model execution. Gate connection loss cancels invocation; every business mutation still independently checks lease or locks effect row.

Checkpointer commits are separate from business transactions. They cannot authorize another side effect: every node consults the business ledger before work. Stale checkpoints may record old progress but cannot overwrite finalized business state. On resume rehydrate current DB state and converge missing checkpoint/status updates. A brief saved in DB but lacking final checkpoint resolves to same unique brief; terminal answer bypasses graph execution and returns existing event history. If saver fails before next node under sync durability, stop; don't continue effects without checkpoint persistence.

## Provider attempts and replay

Before each network request, reserve budget and persist attempt_id, request hash and `issued` execution_state in model_usage within a fenced transaction; this write happens before transport sends. On return persist complete normalized result in model_usage.response with response_stored execution_state plus usage or a typed definite_failure, then return from graph node. SDK automatic retries disabled; router owns bounded retries. Existing append-only event sequence remains committed before exposure.

Crash after issued but before response persistence is ambiguous even if no public draft exists. Do not automatically repeat that attempt or silently fall back: mark run interrupted, record conservative estimated usage, and require a new user run. Conservative treatment also covers crash between issued marker and actual send. Definite provider errors can consume the normal bounded pre-draft retry policy; uncertain transport outcome cannot be made exactly-once with graph tasks. Crash after complete response persisted may resume validate/finalize without calling provider. Any partial public draft without a stored complete response terminalizes interrupted. Ordinary graph replay and SSE reconnect never trigger duplicate generation.

## REST approval coordination

Proposal POST transaction creates tool execution + thread mapping + recovery job; it drives prepare/approval until durable interrupt using a bounded invocation, or returns the existing pending ToolExecution for polling if preparation is still queued. Approval POST first locks tool execution, checks creator/editor, hash, expiry and current sources, records approve/reject and enqueues a workflow recovery job atomically. It may drive resume synchronously within the existing2s operation budget; otherwise returns approved/running ToolExecution with a Location to GET it. Returned200 acknowledges the decision; only status=succeeded with brief_id means the artifact exists. Public UI must not show saved based on HTTP status alone.

The save node rechecks approval and current authority, then locks execution and atomically inserts brief with unique execution_id and marks succeeded. Duplicate resume returns same artifact; transient DB failure is retryable; permission/hash/source failure never is. Maintenance handles approved unfinished threads, expired pending proposals and lost interrupt projection. A decision arriving before checkpoint preparation is persisted stays in DB and is applied after durable interrupt; do not assume an in-memory waiter exists. Deadline expiry is enforced by application even though a graph interrupt can wait indefinitely.

## Lifecycle, versions and tests

Completed answer checkpoints retained≤24h; pending brief≤10min plus24h terminal diagnostics. Conversation/source deletion invalidates thread use immediately and schedules saver.delete_thread for blobs/writes/history, with ownership mapping retained until confirmed. Metadata references may be held in encrypted backups30d with deletion-log replay before restore exposure. Public final history continues in application tables, not checkpoint snapshots. No cross-thread personal memory store is enabled.

T28 implementation checkpoint: bounded `checkpoint-prune` uses public async `adelete_thread` under the invocation gate and writes a deletion receipt only after success. Runners reject receipt-marked mappings under that gate. Mapping receipts remain eligible for reconciliation after1h because the separate saver connection can finish an already-issued write after gate loss. Expired but unfinished jobs/reservations are preserved until recovery resolves them. Conversation purge now transfers thread IDs into standalone workflow_thread tombstones before mapping removal, and checkpoint-prune reconciles those records (ADR018). Periodic fleet scheduling and independent off-host deletion-log retention/replay remain pending; the target retention duration is not yet an operational SLA. See ADR017.

Pin graph_version and state_schema_version in thread mapping/config. Deploys drain active answer graphs; brief graphs wait up to10min. Retain old graph implementation for that window or explicitly expire pending proposals before incompatible deployment. Do not reinterpret a checkpoint after renaming nodes/state. Vendor schema upgrades need backup/restore and compatible rollback tests. GRAPH-RECOVERY covers restart at every boundary, duplicate callbacks, modified hashes, revoked sources, safe codec, competing workers, uncertain issued request and deletion.

Official [persistence](https://docs.langchain.com/oss/python/langgraph/persistence) and [interrupt](https://docs.langchain.com/oss/python/langgraph/interrupts) documents establish checkpoint/thread and node-restart mechanics. The authorization, ledger, concurrency and retention rules above are project design obligations.

## Implemented T17 answer domain

`ai/orchestrator.py` implements AnswerSteps with native adapters, BillingService, immutable PromptManifest, real retrieval/reranking/context and EventStore finalization. The graph also branches context→abstain when a required comparison pair cannot fit, and generate→END after a provider refusal has atomically terminalized. The JSON-only checkpoint schema is unchanged. Business manifest format version1 is defined in `ai/manifest.py` and lives in `runs.execution_metadata.prompt_manifest`; it contains model/query/request/prompt/source/history hashes, ordered IDs, policy version, limits and degradation, with no raw prompt or source text.

Context replay may recompute retrieval before a manifest exists. Once a manifest is committed, prompt preparation cannot replace it or change E-ID bindings. A resumed generate node reloads exactly those passages/history pairs and verifies the original request fingerprint before transport. A response already stored in the attempt ledger goes directly to validation without network or a readiness requirement. Validation/draft progress is replayable: each256-byte UTF-8 draft batch and its cursor commit together, preventing duplicate draft text after a checkpoint failure. Complete provider JSON is never emitted as draft content. Cancellation wins before completion, and provider-interrupted faults retain the interrupted run/message state.

API event replay, completed-message reads, history selection and egress include the selected private history's evidence ancestry. An iterative traversal verifies each saved pair/hash and source run, including indirect ancestors that have fallen outside the newest six pairs. It deduplicates visits and fails closed beyond128 runs; it never silently drops dependency checks. Extremely long dependent histories can become unavailable at this bound; flattening provenance efficiently is a future measured optimization. Every factual answer must still cite evidence from its current request; history is not an authoritative source. Egress and finalization additionally rehydrate/check the full immutable source hashes and live policy version. The last database authorization precedes network delivery; already transmitted bytes cannot be recalled.

Model availability is shared by API/worker through ModelCatalog. Endpoint changes invalidate readiness even when the model key is unchanged. The worker consumes only existing reports; operational probe scheduling remains later routing/observability work. Deterministic source/citation checks do not establish semantic entailment or resistance to every prompt injection.


## Implemented T23 approval and comparison recovery

`brief-worker` owns the separate durable graph. REST returns the committed proposal/decision and a creator-authorized execution polling Location; it does not invoke checkpoints in the API process. Pending jobs park until the10-minute expiry and hold no active slot. Decisions wake the same job; decisions that arrive while it is running are observed before parking. Current editor membership, content/citation hashes, frozen expiry and policy version are rechecked in the save transaction. Failures terminalize in the fenced business ledger outside the graph, including membership loss; no error path can insert a brief. Checkpoint/DB/timeout failures leave the lease for bounded recovery. Three exhausted infrastructure attempts require operator investigation; they do not reset indefinitely. Success committed before a missing final checkpoint resolves to the existing unique artifact.

Comparison read recovery persists at most32KiB of ranked source references and hashes in the private run ledger. It rehydrates text from PostgreSQL after live scope/hash checks; unchanged completed reads do not repeat vector transport. An interrupted read may recover at most three times, while a recorded failed read is not repeated. `compare_revisions` and `save_brief` are deterministic composite entrypoints in the fixed registry. Search and passage reads are internal retrieval/evidence operations, not dynamically selected native model tools. One logical comparison generation uses the same T20 bounded provider retry policy. Native tool calls remain disabled.
