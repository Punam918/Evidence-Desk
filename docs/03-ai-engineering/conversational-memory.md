# Conversation memory

Core memory is private conversation history, not an unbounded vector memory. Persist messages as immutable user/assistant rows with sequence and state. ContextBuilder reads only the current user's conversation in the active workspace, selects at most six completed user/assistant pairs in recency order within 2048 generation tokens, then emits chronological order. Failed/partial messages and tool arguments are not fed back as authoritative answers. Current query remains separate.

Summarization is P1, optional per workspace. Trigger when older completed turns exist beyond recent window; summary max 384 tokens, schema `{facts:[{text,message_ids}],open_questions:[string]}`. Retain identifiers/constraints, no hidden reasoning or instructions from source text. Background summary records covered through sequence, prompt/model version and exact referenced message IDs. Only use summary when current history version matches and references remain accessible. Summary is explicitly untrusted conversational context, below system/developer rules. Never use it as a source citation for product facts; retrieval must find source documents again.

New summary replaces previous atomically under optimistic version check; concurrent chat may make it stale, so discard/retry later. Summary provider obeys workspace privacy and its own budget reservation attributed to conversation; in local-only mode use local or skip. Summary failure never blocks chat: use recent history. Summary + history share 2048-token limit.

Default message/summary retention 90d; user can delete conversation immediately. Documents deleted or membership revoked invalidate referenced summary before next request; deleting conversation removes summary, events, messages, feedback and briefs. No cross-conversation persistent preferences inferred from chats. Explicit future preferences must be separately user-editable with opt-in/expiry; that feature is stretch and has no current write path.

Retrieval rewrite may use last two completed user turns to resolve pronouns; it cannot widen KB scope, invent facts or turn history into system instructions. Compare fixtures with ambiguous “it”, multiple documents, language switches, deleted antecedents and adversarial previous assistant messages. Success = correct context use on labeled follow-ups without increasing unauthorized access or unsupported claims.

## Graph state is not conversation memory

LangGraph checkpoints store reference-only execution progress. Conversation/history/summary policies remain in application tables; each graph node reloads only creator-authorized current content. Never enable a shared LangGraph Store or accumulate raw messages in graph state by default. Thread retention24h is independent of90d conversation history; source revocation invalidates both replay and hydrated memory.

T16 implements the bounded history foundation in `db/history_repository.py` and `ai/context.py`. The current run must belong to the caller, remain queued/running and not be cancelled; the supplied query must match its stored user message. The repository checks the live private conversation, considers only the six most recent completed runs before the current user sequence, and excludes pairs whose recorded evidence is no longer visible. It does not scan unbounded older history to replace excluded pairs. Packing trims oldest pairs to2048 tokens and emits chronological quoted turns. ContextBuilder rechecks history/source visibility after packing; the orchestrator must check again at provider egress. Rewrite/summary experiments remain T21.

T21 implements opt-in experiments in `ai/rewrite_experiment.py` and `ai/summary_experiment.py`. Neither is enabled in the serving worker. Native request schemas are distinct from answers; the same usage ledger accounts auxiliary purposes inside the run cap. Rewrite is English-pronoun-only, uses the last two user messages and preserves the original generation question. Summary uses at most six older pairs beyond the recent six, with exact message provenance and optimistic conversation-version storage. `compose_memory` keeps recent history first within the shared2048-token cap. Both experiment histories participate in the iterative source-ancestry checks, even if normal prompt packing omits those messages.

Implementation clarification: these are fenced run-bound experiments before generation, not a scheduled background summary worker. Automatic summary scheduling/serving use and V3 promotion require T24/T25 paired evidence; no semantic promotion is claimed from structural fixtures. Optional invalid/stale/definite failures degrade to baseline. Ambiguous or timed-out issued auxiliary requests retain estimated accounting and interrupt under the same no-uncertain-replay invariant as generation. See `docs/10-testing/memory-experiment-report.md` for the designed ablations and explicit limits.

2026-10-19 rewrite hardening (ADR022): signed quantities, percentages, technical identifiers and quoted literal phrases must survive optional follow-up rewriting. English polarity checks now include contractions and introduced/dropped negation counts. Violations use the original query without expanding scope. Conservative literal rejection is not a semantic-equivalence guarantee; multilingual negation detection and serving promotion remain unevaluated.
